# ColdChain ESP32 Wokwi Hardware Simulation

This directory contains the complete IoT hardware simulation for **Task 1** and **Task 3** of the ColdChain Hackathon Challenge.

---

## 🔌 Hardware Pinout Mapping

| Component | ESP32 Pin | Type | Purpose |
|:---|:---|:---|:---|
| **OLED Display (SSD1306 128x64)** | **GPIO 21 (SDA), GPIO 22 (SCL)** | I2C | Real-time temperature & Safe / Warning / Breach visualizer |
| **DHT22 Temperature Sensor** | **GPIO 4** | Digital Input | Cold-room ambient sensor (Simulate 2°C – 15°C) |
| **Compressor Relay** | **GPIO 5** | Digital Output | Pulls down temperature (ON $\ge 7^\circ\text{C}$, OFF $\le 3^\circ\text{C}$) |
| **Door Switch Button** | **GPIO 18** | Input Pullup | Detects open door. State change immediately publishes MQTT |
| **Power Failure Button** | **GPIO 19** | Input Pullup | Simulates AC Grid failure and switches to Battery mode |
| **Piezo Buzzer** | **GPIO 13** | PWM Output | Activates when door remains open for $> 60$ seconds |
| **Red LED** | **GPIO 2** | Digital Output | Discard alarm / breach alert (latched until Admin reset) |
| **Green LED** | **GPIO 14** | Digital Output | Safe cold chain status indicator (2°C – 8°C) |

## 🚀 How to Run the Simulation

### Option A: Online on Wokwi Web (Fastest — 1 Click)
1. Go to [https://wokwi.com/projects/new/esp32](https://wokwi.com/projects/new/esp32).
2. Copy the contents of `sketch.ino` into the **sketch.ino** tab.
3. In the **diagram.json** tab, replace the contents with `diagram.json`.
4. In the **Library Manager** (libraries.txt tab), ensure the following are installed:
   ```
   PubSubClient
   Adafruit SSD1306
   Adafruit GFX Library
   DHT sensor library
   ArduinoJson
   ```
5. Click **Start Simulation (Play button)** ▶️.

### Option B: In VS Code with Wokwi Extension
1. Install the **Wokwi Simulator** extension in VS Code.
2. Open `wokwi/diagram.json` and press `F1` ➔ `Wokwi: Start Simulator`.

## 🧪 Hackathon Verification Scenarios

### 1. Compressor Hysteresis & 60-Second Off-Delay (Task 1)
* Click the **DHT22 sensor** and slide the temperature above **$7.0^\circ\text{C}$**:
  * The **Compressor Relay** turns **ON** immediately (Relay LED lights up, OLED shows `COMP: ACTIVE (ON)`).
* Slide the temperature down to **$3.0^\circ\text{C}$** or below:
  * The **Compressor Relay** turns **OFF** (OLED shows `COMP: OFF (Delay: 60s)`).
* Slide temperature back to **$7.5^\circ\text{C}$ immediately**:
  * Notice the compressor **DOES NOT turn ON** yet! The OLED countdown shows the remaining protection seconds until the 60-second delay has safely elapsed to prevent motor short-cycling.

### 2. Door Open > 60s Breach Alert (Task 3)
* Click the red **Door Switch** button:
  * An immediate MQTT packet is published to the backend.
  * OLED shows `DOOR: OPEN (X s)`.
* Leave the door open for over **60 seconds**:
  * The **Piezo Buzzer** sounds an audible pulsing alarm.
  * The Red LED flashes continuously.
  * The backend triggers multi-channel alerts (Telegram & Email).
* Close the door:
  * Buzzer silences immediately and state resolves.

### 3. Power Failure Simulation (Task 3)
* Press the orange **AC Grid/Battery** button:
  * ESP32 immediately switches to `BATTERY` power mode and publishes an alert packet over MQTT.
  * The web dashboard displays the power outage warning instantly.

### 4. 30-Minute Edge Buffering & Deduplication (Task 3)
* When network is interrupted, the ESP32 buffers up to **360 readings** (30 minutes of 5-second intervals) in local RAM.
* Upon reconnection, it flushes the buffered readings chronologically to `coldchain_fastrobox/fridge_1/offline_sync` without duplicate packets.

### 5. Cryptographic Device Security (Task 4)
* Every packet generated by the ESP32 is signed using native hardware **HMAC-SHA256**:
  $$\text{Signature} = \text{HMAC-SHA256}(\text{timestamp} \,\|\, \text{nonce} \,\|\, \text{payload}, \text{SecretKey})$$
* Any altered payload or replayed nonce is rejected by the backend security layer.
